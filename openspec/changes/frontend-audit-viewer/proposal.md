## Why

Initiative q3-audit-log makes every admin-path mutation write a team-audit event, but nobody can read the trail: `QueryAuditLog` is edge-routed to admins yet has no UI. Operators need to answer "who touched this order, listing or user, and when" without a database client. This slice adds a server-rendered admin page, `/admin/audit`, over the filtered `QueryAuditLog` that audit-query-filters ships.

initiative: q3-audit-log

depends_on: audit-query-filters (the `target_id`, `action`, `created_after`, `created_before` filters in team-audit, and the e2e helper `platform-e2e/tests/e2e/support/audit_support.py`). The proto copy in `team-frontend/proto` is regenerated by the contract slice q3-audit-log-contract; this slice never edits proto copies, it only runs `npm run proto` to regenerate `src/generated`.

## What Changes

- New page `src/app/(shop)/admin/audit/page.tsx`, server-rendered, `dynamic = "force-dynamic"`, gated exactly like `admin/cockpit/page.tsx`: no principal or token redirects to `/login`; a principal without the `admin` scope gets the same `Result status="403"` ("Cần tài khoản Quản trị") with audit-specific sub-text; a gateway `PermissionDenied` renders the same 403; `Unauthenticated` redirects to `/login`.
- New gateway client `src/lib/gateway/audit.ts` (`server-only`): `queryAuditLog(filters, cursor)` calling `AuditService.QueryAuditLog` through `makeClients(token)`; `makeClients` in `client.ts` gains an `audit` client. It maps the proto to plain view types and returns a discriminated result (`ok`, `unauthenticated`, `forbidden`, `invalid_range`, `unavailable`); it never throws and never returns `err.message`.
- Filters live in the URL query string, so a result is linkable and survives reload: `target_type`, `target_id`, `actor_id`, `action`, `from`, `to` (dates, `YYYY-MM-DD`), `cursor`. A GET form on the page sets them (no client state, works without JS).
- Table of events newest first (the server order is kept), columns time, actor, action, target (`type/id`), metadata (`key=value` pairs, keys sorted). 20 rows per page (`pageSize: 20`). A "Trang sau" link carries the response `next_cursor` and all current filters; it is absent when `next_cursor` is empty.
- Dates: `from` and `to` are calendar days in Vietnam time (UTC+07:00) and both are inclusive. The page sends `created_after = from 00:00 +07:00` and `created_before = (to + 1 day) 00:00 +07:00` because the server upper bound is exclusive. `to` earlier than `from` reaches the server and its `InvalidArgument` is shown as a Vietnamese error. An unparseable date is shown as a Vietnamese error without any gateway call.
- Empty result: "Không có sự kiện nào".
- `CockpitView`/cockpit page gains a link "Nhật ký kiểm toán" to `/admin/audit`.

No gateway, team-audit or proto change here. No new dependency. UI copy is proposed in Vietnamese below for human review.

## NFR

- Page render is one gateway call (`QueryAuditLog`) after the session check; the gateway/team-audit p95 budget (300 ms for a filtered query, non-gating) applies. Client timeout 5 s as in `cockpit.ts`; a timeout maps to the `unavailable` state, not a crash.
- Page size fixed at 20 (server max 100); the page never requests more and never loops over pages.
- Availability: team-audit down degrades only this page (error banner, filters stay usable); no other page depends on it.
- No client JS is required for filtering or paging (GET form and plain links), so there is no hydration cost beyond the shell.

## Data classification

- Audit events shown: admin user id (`actor_id`), target type and id, action, metadata (for `kyc.review` the subject `user_id`, for refunds `order_id` and `amount`). Per the initiative these hold ids and catalogue keys only, no names, documents, addresses or free text beyond existing reason fields. Purpose: accountability of privileged actions (Decree 13/2023 processing records). Basis: legal obligation / legitimate interest. Retention: team-audit policy; the frontend stores nothing.
- Filter values (actor id, target id) travel in the URL query string. They are opaque ids, not contact data, but they land in server access logs and browser history; the page uses GET deliberately and sets `Referrer-Policy` through the existing app default (no third-party links or scripts on the page). No analytics event is fired from this page and filter values are not sent to the tracker.
- No new cookies, local storage or client persistence. The session bearer stays server-side (`server-only`).

## Threat model

- Assets: the audit trail (confidential to admins), admin session token.
- Abuse cases:
  1. A non-admin or guest opens `/admin/audit`: guest redirected to `/login`, non-admin sees the 403 Result and no query is sent. The scope decode only gates rendering; the gateway (`adminProcedures`) enforces `admin` on the data, and its `PermissionDenied` renders the same 403.
  2. A non-admin forges a request with stale scopes in the cookie: gateway answers `PermissionDenied`, the page shows the 403 and no rows.
  3. Injection through metadata or ids (for example `<script>` in a value): everything is rendered as React text, never as HTML; filter values are passed as typed proto fields, not interpolated.
  4. Oversized or hostile query params: each param is trimmed and capped (ids and action 128 chars, cursor 256), extra params ignored, an array-valued param takes its first value.
  5. Cursor tampering: the cursor is opaque and passed through; the server validates it and an invalid one yields the `unavailable` or empty path, never a crash.
  6. Read-only: the page has no write RPC and offers no edit or delete of events.
- Authz rule: render only when `principal.scopes.includes("admin")`; the gateway decides.

## Open assumptions

- Vietnam time (UTC+07:00) is used for the day boundaries; there is no per-user timezone in the product.
- The frontend proto copy has no `platform/audit` directory today; this slice assumes the contract slice adds it (initiative lists team-frontend among consumers).
