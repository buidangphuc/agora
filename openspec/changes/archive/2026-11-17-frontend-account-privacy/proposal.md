## Why

Backlog Q24 gives a signed-in user rights over their data: see and change consent, download their data and delete the
account. The backend slices (identity-legal-consent, identity-account-deletion, identity-data-export) expose them
through `PrivacyService`, but no screen reaches them: `team-frontend` has no `/account/privacy` route and the account
menu (`src/features/account/AccountShell.tsx` `ACCOUNT_MENU`) has no privacy entry. Consent today lives only in the
`agora_consent` cookie (`src/lib/consent/consent.ts`).

initiative: trust-legal

## What changes

- New route `/account/privacy` in team-frontend (guest redirected to login), rendered inside `AccountShell` with a new
  menu key `privacy` ("Quyền riêng tư") and a link from the `ConsumerShell` account menu.
- Consent card: current state per purpose (analytics, marketing, personalization) from `ListMyConsents`, a save form
  that calls `RecordConsent` (source `account`, one record per changed purpose) and then writes the `agora_consent`
  cookie, and the history newest first, 20 per page. Legal acceptance rows (TERMS, PRIVACY_POLICY, SELLER_TERMS) appear
  in the history read-only.
- Export card: one button calls `ExportMyData` and downloads the JSON as a file in the browser; nothing is stored.
- Deletion card: password-confirmed request (`RequestAccountDeletion`), the pending state with the `erase_after` time
  and a cancel button (`CancelAccountDeletion`), status read through `GetAccountDeletionStatus`, and a blocker message
  when the request fails `FAILED_PRECONDITION`.
- New server-only gateway module `src/lib/gateway/privacy.ts` and server actions in `src/features/privacy/actions.ts`
  following `src/lib/gateway/sessions.ts` and `src/features/account/actions.ts`.

Contract consumed (from trust-legal-contract, not redefined here): `PrivacyService.{RecordConsent, ListMyConsents,
RequestAccountDeletion, CancelAccountDeletion, GetAccountDeletionStatus, ExportMyData}`, `ConsentPurpose`,
`ConsentRecord`. `team-frontend/proto` is regenerated by the contract slice; this slice never edits proto copies.
The banner (Vietnamese labels, recording on save) and the Terms re-acceptance prompt belong to frontend-legal-pages.

## Non-goals

Legal page content, footer, sign-up acceptance, banner text (frontend-legal-pages). Consent for anonymous visitors
(cookie only). Exporting data held by other services (export v1 is identity data only; the page links the in-app views of
orders, reviews and chats). Seller-app privacy screens. Changing the 48 h cancel window (backend).

## Non-functional requirements

- The page is `force-dynamic`, server-rendered, and shows its first content within the existing account page budget
  (same pattern as `/account/security`); a failing read shows an inline retry, never a blank page.
- Each action has a pending state that blocks a double submit; the export download starts within 1 s of the gateway
  answer for the 1 MiB maximum.
- Export bytes are held in memory only for the download: no `localStorage`, no cookie, no server cache, no log.
- All copy is Vietnamese; focus, labels and `aria-live` errors follow the existing `AccountShell` pages.

## Data classification

| Field | Class | Purpose | Basis | Retention in this slice |
|---|---|---|---|---|
| Account password typed to confirm deletion | credential | re-authentication for `RequestAccountDeletion` | contract (initiative decision) | never stored or logged; lives in the form and one server action call, cleared on submit and on error |
| Export JSON (account, addresses, sessions, login history, consents) | personal | data-subject access | Decree 13/2023 access right (unverified, see initiative NEEDS_HUMAN) | in memory until the browser saves the file; not persisted by the app |
| Consent records (purpose, granted, version, time) | personal | proof of consent shown back to the user | consent evidence | read-only display; storage is team-identity's |
| Deletion state (`erase_after`) | personal | tells the user when erasure happens | data-subject request handling | read-only display |

## Threat model

- Assets: the user's account (deletion is irreversible after `erase_after`), the export file (full personal data
  dump), the password.
- Abuse cases: (1) someone at an unattended, signed-in browser deletes the account or downloads the export; mitigated by
  the password re-entry for deletion (server-checked by team-identity) and by the export being available only to the
  signed-in session (residual risk accepted, no step-up for export per initiative decision); (2) CSRF on actions;
  mitigated by Next.js server actions (origin-checked POST) and no GET route that changes state or returns the export;
  (3) leaking the password, export or raw gateway text through logs or error toasts; mitigated by fixed Vietnamese
  messages and no logging of arguments or results; (4) a forged call for another user; impossible, the user id comes
  from the principal in team-identity and the frontend sends none.
- Authorization rule: every action and the page require a user session; the gateway rejects anonymous callers
  `UNAUTHENTICATED`; the frontend never sends a user id.
