# Design

- Names, field numbers and types follow the Contracts section of `plans/q11-checkout-coherence/00-spec.md` (Locked), after re-verification against `platform-core/packages/proto` (main, q10-order-lifecycle not yet merged): `CreateOrderRequest` 5-7, `CalculateShippingFeeResponse` 4-5, `ValidateAndReserveResponse` 5-6, `Order` 25-27 are all free. `Order` 18-24 are reserved for q10-order-lifecycle and are not touched. If q10 lands first and adds to `CreateOrderRequest` or `CalculateShippingFeeResponse`, the numbers are re-verified and shifted at build time (task 1.1) before this slice is committed; the build of this slice waits for q10 to merge.
- `order.proto` does not import `promotion.proto` (C8). `VoucherQuote.scope` uses a local enum `CheckoutVoucherScope` (`CHECKOUT_VOUCHER_SCOPE_UNSPECIFIED = 0`, `_SHOP = 1`, `_PLATFORM = 2`), mirroring `platform.promotion.v1.VoucherScope`; the compat test pins that both enums have the same value names (after the prefix) and numbers. team-order maps one to the other. `promotion.proto` is re-copied only to the five repos that already hold it.
- Closed behaviours documented in comments, not new fields: platform reservation id `platform:<checkout_id>`; proration remainder to the largest group (ties lowest seller_id); address errors as gRPC codes with fixed messages "address not found" / "address changed" / "cart is empty".
- Voucher error codes at `CreateOrder` (settled, matches order-multishop-checkout): a code in the wrong slot or on another shop's group → `FAILED_PRECONDITION` with the promotion reason; a second `shop_vouchers` entry for one `seller_id`, or `voucher_code` set together with `platform_voucher_code` or repeating a `shop_vouchers` code → `INVALID_ARGUMENT`. Nothing stays held. In `PreviewCheckout` a refused voucher is reported through `VoucherQuote.valid=false` with the reason instead.
- Test location: `platform-core/packages/proto/platform/order/v1/`, same buf-descriptor + stdlib wire codec approach as the flash stock test.
