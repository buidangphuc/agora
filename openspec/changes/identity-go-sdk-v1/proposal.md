## Why

team-identity hand-rolls the platform layer that go-sdk v1.0.2 provides, and it carries dependency flags and runtime fallbacks that the user has removed from the platform. Today `OpenResources` refuses to run without `DATABASE_ENABLED=true`, `KAFKA_ENABLED=false` swaps in a `NoopPublisher` (revokes are recorded but nothing is ever relayed, so the gateway never denylists a revoked session), `OUTBOX_ENABLED` and `SESSION_SWEEP_ENABLED` switch two background workers off, an empty `UPSTREAM_AUDIT_ADDR` yields a nil audit client, and `AuthService.WithSessions` is optional so a service built without a session store logs users in with no session row. The gRPC server uses a hand-written request-id, tracing and principal interceptor chain with no panic recovery, health is a DB ping loop on one service name (so a database blip restarts pods when probes use the same name), the outbox relayer and its Kafka publisher are local code with an attempt limit that parks transient failures, and logs at relay failure paths are local.

Decisions of 2026-10-22/23 (user, recorded in `plans/go-sdk-migration/PLAN.md`): services depend on the tagged module `github.com/buidangphuc/agora/platform-core/packages/go-sdk@v1.0.2`; importing a dependency means using it (no enable flags, no runtime in-memory or noop fallbacks); mock means mock data served by the real service. team-identity has no external adapter to mock, so it takes no `MOCK_DATA` group.

initiative: go-sdk-migration

## What Changes

- **Dependency**: `go.mod` requires `github.com/buidangphuc/agora/platform-core/packages/go-sdk v1.0.2`; no `replace`, no `third_party`. golangci-lint is pinned as a `tool` like the SDK `go.mod`. `Makefile` includes `../platform-core/make/go-service.mk` and lints with `../platform-core/packages/go-sdk/.golangci.yml` (no copies). No doc comments are added (revive doc-comment rules are off).
- **Layout (ADR-0016)**: `cmd/server/main.go` -> `internal/app.Run(ctx, settings)`; `internal/config`; `internal/rpc` (replaces `handler`, `interceptor`, `grpcserver`); `internal/identity` (replaces `service`); `internal/store` (replaces `repository`, owns the embedded `migrations`, plus the test fakes in `internal/store/storetest`); `internal/events` (envelope builders and the relay log redaction; the local relayer and publisher are deleted); `internal/upstream` (audit writer over `auditx`); `internal/token`, `internal/authz` stay.
- **Settings**: `config.Settings` = SDK `Runtime`, `GRPC`, `Postgres`, `OTel`, `Kafka`, `Outbox`, `Audit`, `LogKeyFP` plus service groups `Events`, `JWT`, `SeedAdmin`, `PasswordReset`, `Retention`. `ENV`, `GRPC_PORT`, `DATABASE_URL`, `JWT_PRIVATE_KEY`, `JWT_KID` are required (no defaults). **BREAKING (accepted)**: deleted variables `DATABASE_ENABLED`, `KAFKA_ENABLED`, `OUTBOX_ENABLED`, `OUTBOX_MAX_ATTEMPTS`, `SESSION_SWEEP_ENABLED`, `UPSTREAM_CALL_TIMEOUT_SECONDS` (the SDK bounds each audit write at 2 s, the old default); renamed `SHUTDOWN_GRACE_SECONDS` -> `SHUTDOWN_GRACE` (duration) and `OUTBOX_CLAIM_LOCK_SECONDS` -> `OUTBOX_CLAIM_LOCK` (duration); new `SHUTDOWN_DRAIN_DELAY`, `LOG_KEY_FP_SECRET`. `GRPC_REFLECTION_ENABLED` now defaults to off (it was on) and is refused in a strict ENV; local tooling that relies on reflection sets `GRPC_REFLECTION_ENABLED=true` (README). `UPSTREAM_AUDIT_ADDR` is required in every ENV (no fallback mode); `KAFKA_BROKERS` and `LOG_KEY_FP_SECRET` are required in a strict ENV; new `OUTBOX_PURGE_RETENTION` (168h) and `OUTBOX_PURGE_INTERVAL` (1h). Kept: `OTEL_ENABLED`, `GRPC_REFLECTION_ENABLED`, `SEED_ADMIN_ENABLED`, every `SESSION_*`/`LOGIN_HISTORY_RETENTION` duration, `JWT_*`, `JWKS_HTTP_PORT`, `PASSWORD_RESET_EXPOSE_TOKEN`, `IDENTITY_EVENTS_TOPIC`.
- **Database and migrations**: `postgres.Open` (pings, fails fast); an unreachable database fails boot in every ENV. Migrations `0001`-`0008` move into the binary (`go:embed`); version numbers are unchanged. **The service never migrates at boot**: the binary gains the subcommand `server migrate up` (SDK `migrate.Up` over the embedded migrations, loading only `ENV` and `DATABASE_URL`); compose keeps `team-identity-migrate` running the service image with `migrate up`, and gitops runs it as an Argo PreSync Job per service (Deploy track, change `deploy-go-sdk-v1`). New migrations `0009`-`0018` upgrade the existing `identity_outbox_events` table to the SDK outbox schema (`outbox.UpgradeSQL`) without losing pending rows or their order; `0019` requeues rows the old relayer parked as `failed` (the removed attempt limit would otherwise leave them blocking their aggregate and a parked `SessionRevoked` never denylisted) and moves unpublished `Session` rows to the `User` aggregate.
- **Outbox and Kafka**: revoke, reuse-revoke, refresh-revoke, enforcement revoke and `UserStatusChanged` rows are written with `outbox.Store.EnqueueTx` inside the same transaction as before; the SDK `outbox.Relayer` over `kafkax.Producer` publishes them to `IDENTITY_EVENTS_TOPIC` keyed by user id. `NoopPublisher`, `KafkaPublisher`, the local relayer, `InMemoryOutbox` (runtime) and the `OUTBOX_MAX_ATTEMPTS` parking rule are deleted. Envelope bytes and `event_id` are unchanged, so the gateway denylist consumer is unaffected. **Published rows are purged** after 7 days by `outbox.Store.Purge`, run on a schedule inside the service (`lifecycle.Every`, `OUTBOX_PURGE_INTERVAL` 1h, `OUTBOX_PURGE_RETENTION` 168h). **Behaviour changes (accepted)**: transient publish failures retry forever with capped backoff and only a permanent record error parks a row (rows already parked by the old relayer are requeued by `0019`); published records gain the `event-id`, `event-type`, `x-request-id` and `traceparent` headers; per-user order across `SessionRevoked` and `UserStatusChanged` is guaranteed by the SDK per-aggregate sequence.
- **Audit**: `auditx.Dial` + `auditx.Gate` replace `upstream.AuditClient`/`ErrAuditNotConfigured`; with a failing writer `SetUserStatus` returns `Unavailable` `audit trail unavailable` and changes nothing. The audit call still goes out as service principal `service-team-identity` holding `audit.write`.
- **Sessions are always on**: `AuthService` is built with its session store as a required argument; the sessionless login path (`WithSessions` unset, no refresh token, `sid` empty) is deleted.
- **Health**: `healthx` with a `postgres` checker; readiness (`""`) is the overall status, `liveness` is independent of dependencies; gitops sets `probes.livenessService: liveness`. Kafka is not a readiness check in any service (design D6).
- **Auth and errors**: the hand-written principal interceptor is replaced by `auth` (`UnaryServerInterceptor`, `RequirePrincipal`, `RequireScopes`, `RequireService`, `RequireUser`); handler errors go through one `grpcx.ErrorTable`. **Behaviour changes (accepted)**: a cancelled or timed-out request returns `Canceled` / `DeadlineExceeded` instead of `Internal`; an unmapped unique violation (`23505`) returns `AlreadyExists`; the text of `PermissionDenied` from scope checks is the SDK text (`missing scope`, `principal type not allowed`); the code of every authorization outcome is unchanged and the explicit messages `tài khoản bị khóa`, `username already exists`, `invalid credentials`, `invalid input`, refresh `Unauthenticated` text are kept by table rules.
- **JWT and JWKS**: claims and the JWKS document use `jwtx.Claims` / `jwtx.JWKS` so issuer and verifier share one contract; signing stays RS256 with `golang-jwt`; the JWKS HTTP listener becomes `lifecycle.HTTP` on `JWKS_HTTP_PORT` and drains with the rest; the document, `Cache-Control: public, max-age=300` and method rules are unchanged.
- **Retention sweeper and outbox purge**: both always run (`lifecycle.Every(..., RunAtStart)`: `SESSION_SWEEP_INTERVAL` for sessions and login history, `OUTBOX_PURGE_INTERVAL` for published outbox rows), stop before the pool closes; log lines carry counts only.
- **Logs and privacy**: `logx` (JSON, service attribute, request id, principal id, trace ids); the SDK outbox relayer logs `aggregate_id` (a user id) when a row fails, so the relayer logger is wrapped to replace `aggregate_id` by `key_fp` (12 hex HMAC-SHA256 under `LOG_KEY_FP_SECRET`); no password, token, hash, reset token or status note is logged.
- **Unchanged**: every RPC and the proto, scopes per role, status enforcement semantics (Q1 session continuity, login enforcement, refresh rotation, reuse detection, grace replay), the schema of every table other than the outbox table, cursors (`ListUsers` last username, login history decimal offset; `pagination.Clamp` only, `EncodeOffset` is NOT used), `SEED_ADMIN_*` semantics.
- **Not used (reason in design.md)**: `idempotency`, `flags`, `resilience`, `consume`, `mockdata`, `upstream` directly (only through `auditx.Dial`), `pagination.EncodeOffset`.
- **Deploy track** (change `deploy-go-sdk-v1`, listed in tasks.md; the shared deploy-runtime requirement "Services refuse unsafe configuration in staging and production" is MODIFIED only there, this change carries no copy): compose migrate service with `migrate up` and `GRPC_REFLECTION_ENABLED=true`, Argo PreSync migrate Job, Recreate on the first rollout, remove `DATABASE_ENABLED`, `KAFKA_ENABLED`, `OUTBOX_ENABLED`, `OUTBOX_MAX_ATTEMPTS`, rename `OUTBOX_CLAIM_LOCK_SECONDS`, add `LOG_KEY_FP_SECRET`, gitops baseline, argocd inline and overlays, `probes.livenessService`.

## Impact

Code: `team-identity/**` only (the `migrate up` subcommand is in `cmd/server`). Contract: none (proto, gateway and event envelope untouched). Existing specs stay valid; the Go test names cited by `session-retention`, `user-enforcement`, `session-refresh`, `auth`, `login-enforcement`, `identity-session-rotation-client` are kept and move packages (map in design.md D2); three requirements are MODIFIED because they name removed flags or fallbacks.

## NFR

- Availability: with Postgres down, readiness (`""`) is NOT_SERVING within one `healthx.DefaultInterval` while `liveness` stays SERVING, so a database outage does not restart pods; with Kafka down, login, register, refresh and revoke keep working (the outbox row waits) and readiness stays SERVING. On SIGTERM both health names turn NOT_SERVING first, then the gRPC server, the JWKS listener and the sweeper stop within `SHUTDOWN_GRACE` (default 10 s), and the relayer stops after the gRPC server.
- Boot: an unreachable database fails `Run` within the SDK 5 s ping bound with a non-zero exit; `server migrate up` exits non-zero on a migration failure or dirty state; an unparsable signing key or the development key in a strict ENV fails boot before any connection.
- Latency (unchanged targets, local Postgres): `Login`, `Register`, `RefreshSession` p99 under 300 ms (bcrypt cost dominates `Login` and `Register`); `RevokeSession` and `SetUserStatus` p99 under 300 ms excluding the audit call, which is bounded at 2 s; JWKS GET p99 under 20 ms.
- Limits: access token TTL `JWT_TTL_SECONDS` (3600), refresh 30 days sliding with 90-day absolute cap, page size 20 default and 100 maximum, `ListUsers` query at most 64 bytes, `note` at most 500 characters, outbox batch `OUTBOX_BATCH_SIZE` (100), sweep batch `SESSION_SWEEP_BATCH_SIZE` (500).
- Durability: a revoke, a status change and its outbox rows commit together or not at all; a published event is delivered at least once keyed by user id; no code path returns success for a session or status change without its durable row.

## Data classification

No new personal field is collected. The existing fields are kept, plus two non-personal trace fields:

| Field | Class | Purpose | Basis | Retention |
|---|---|---|---|---|
| `users.username`, `users.password_hash` | identifier, credential (bcrypt hash) | sign-in | contract (account) | life of the account |
| `users.status`, `status_reason`, `status_until` | enforcement state (reason code) | enforce platform rules | legitimate interest (fraud, safety) | life of the account |
| `sessions` (ip, user agent, device label, `refresh_hash`, `prev_refresh_hash`) | pseudonymous device data, credential hash | session list, revoke, theft detection | legitimate interest (account security) | purged `SESSION_RETENTION` (720 h) after revoke or expiry |
| `login_history` (ip, user agent, outcome) | pseudonymous device data | account security review | legitimate interest | purged after `LOGIN_HISTORY_RETENTION` (4320 h) |
| `addresses` | contact data (name, phone, street, city) | delivery | contract | until the user deletes it |
| `password_reset_tokens` (hash only) | credential hash | recovery | contract | 15 min validity |
| `identity_outbox_events.payload` | user id, session id (no note, no username) | event delivery to the gateway | legitimate interest | published rows purged after 7 days (`OUTBOX_PURGE_RETENTION` 168 h) by `Store.Purge`; pending and parked rows are kept |
| `identity_outbox_events.request_id`, `traceparent`; Kafka headers `x-request-id`, `traceparent` | technical trace ids, not personal data | trace continuity across the relay | legitimate interest | with the row, so as long as the row |
| audit event metadata (`status`, `reason_code`, `note`, `until`) | operator free text | evidence of enforcement | legitimate interest | team-audit platform log retention |

Logs: the service never logs a password, access or refresh token, refresh hash, reset token, address, ip, user agent or `note`; the principal id is the only user id in a log line (added by the SDK logger), and relay failure lines carry `key_fp` instead of the user id. Log retention follows the platform log retention. No DPO sign-off is required (user rule).

## Threat model

- Assets: password hashes, the RSA signing key, refresh tokens (only their hashes are stored), session rows, the enforcement status, the integrity of `SessionRevoked` and `UserStatusChanged` events, the audit trail of status changes.
- Abuse 1, token forgery or a stolen dev key: the dev signing key committed to the repo runs in staging or prod. Control: `config.Load` and boot refuse (error text `refusing to start: ...`) `JWT_KID=dev-2026` and the dev key fingerprint when `ENV` is strict, before connecting to anything; the private key is never logged or exposed, only public keys leave through JWKS.
- Abuse 2, silent loss of revocation: Kafka is down or misconfigured and revokes are never relayed. Control: no noop publisher exists; `KAFKA_BROKERS` is required in a strict ENV; the row stays pending and is retried with backoff; the revoke commits with its row.
- Abuse 3, admin action without a trail: audit is unreachable or unset. Control: `auditx.Gate` writes first and refuses with `Unavailable` otherwise; `UPSTREAM_AUDIT_ADDR` is required in every ENV; self and other-admin targets are refused before audit.
- Abuse 4, privilege escalation through the status RPCs or profile reads: a user calls `SetUserStatus`, `ListUsers` or `GetPublicProfiles`. Control: `auth.RequireScopes(ctx, "admin")` and `auth.RequireService(ctx, "identity.read")` as the first statement of each handler; anonymous gets `Unauthenticated`, a non-admin gets `PermissionDenied`.
- Abuse 5, information leak: driver or storage text in an error, reflection in production, secrets in logs. Control: `grpcx.Status` maps unmapped errors to `internal error`; reflection is off by default and refused in a strict ENV; tests capture logs and spans for the password, tokens, hashes, reset token and note; relay failure logs carry `key_fp` only.
- Abuse 6, reset-token exposure: `PASSWORD_RESET_EXPOSE_TOKEN=true` in a deployed ENV allows account takeover. Control: refused at config load in a strict ENV.
- Abuse 7, a dependency outage cascades into restarts: Control: separate `liveness` service, Kafka not a readiness check.
- Abuse 8, two relayers publishing out of order during the outbox upgrade, or `0019` requeueing rows while the old relayer still runs. Control: the first rollout scales old pods to 0 before the migrate Job and the new pods start (Recreate once); human task 4.3.
- Authz rule: `Login`, `Register`, `RefreshSession` are public (no principal); session, address and profile RPCs need an authenticated user principal and are self-scoped; `AccountAdminService` needs scope `admin`; `GetPublicProfiles` needs a service principal with `identity.read`; health carries no data and needs no principal.
