## Decisions

- Target is the authenticated principal only; the request has no user id.
- Atomic write: one DB transaction sets role, terms columns and inserts the outbox row (same pattern as `SetStatus`/`RevokeSession` enqueue functions). The status check and role write happen under a row lock so a concurrent `SetUserStatus(RESTRICTED)` and `BecomeSeller` serialise; ACTIVE is re-read inside the transaction.
- Token: `SignWithSession(user, scopes from ScopesForUser(roles incl. seller, status), sid, status, ttl)` with the caller's `sid`; no `RotateRefresh`, so the refresh token is unchanged and `AuthResult.RefreshToken` is empty.
- `SELLER_TERMS_VERSIONS` is a comma list; the first entry is current and is the only accepted value, compared byte for byte (no trim, no case folding). Older entries exist for record only.
- An existing seller who is not ACTIVE is refused before the idempotent path.
- Gateway: authenticated, user-type principal, no extra scope (like `CreateHandoffCode`), not in the public-RPC list.
- The seller app sends its configured current version (`SELLER_TERMS_VERSION`), which must equal the first `SELLER_TERMS_VERSIONS` entry; the gap row G15 removal belongs to slice `seller-onboarding-ui`.
- Audit (user decision 2026-11-05): a first grant writes `auth.become_seller` (actor the user; metadata terms version and `result=granted`; never a token) fail-closed, using the same pattern as admin mutations and the hand-off mint: the audit write happens inside the grant transaction before commit, so a failure rolls back role, terms fields and outbox row. Failure maps to `UNAVAILABLE` with `ErrorInfo{identity.platform, AUDIT_UNAVAILABLE}` (same reason string and shape as `promotion-admin-vouchers`; the gateway already returns upstream `UNAVAILABLE` + `ErrorInfo` with a generic message, per that change). An idempotent repeat call by an existing seller does not audit and emits no event: nothing changed, so there is nothing to record, and it keeps working while team-audit is down.
- Audit catalogue: `auth.become_seller` is not in the `WriteAuditEventRequest` catalogue comment (24 entries) in `platform-core/packages/proto/platform/audit/v1/audit.proto`, which `platform-core/packages/proto/gaps_contract_docs_test.go` pins to the header `Action catalogue (24)`. It must become 25 with the new action; this is a contract edit (see tasks 1.6 and the open issue in the change's handover).
- seller-onboarding-ui: its `UNAVAILABLE` scenario already shows a generic retryable error line ("Không thể ...") with no cookie change, which covers `AUDIT_UNAVAILABLE` (also `UNAVAILABLE`); that change is not reopened.
