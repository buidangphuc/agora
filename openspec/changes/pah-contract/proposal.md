## Why

Two follow-up slices of the privacy-audit-hardening initiative need contract changes that must land first, in `platform-core/packages/proto`, and then be vendored byte-identically into consumer repos (ADR proto-copy convention, enforced by `consumer_copies_test.sh`-style checks):

- Hiding a review (`EngagementService.HideReview`) must become a fact on `engagement.events` so team-analytics can record `review_hidden` and the featurestore can exclude the review. No message for it exists in `platform/engagement/v1/events.proto` (only `ReviewCreated`).
- Admin-created SHOP vouchers must be audited as `voucher.admin_create`. The action catalogue comment in `platform/audit/v1/audit.proto` lists 17 actions and does not include it. `action` is a free string on `WriteAuditEventRequest`, so only the catalogue comment changes.

initiative: privacy-audit-hardening

## What Changes

- **`platform-core/packages/proto/platform/engagement/v1/events.proto`**: add message `ReviewHidden { string review_id = 1; string listing_id = 2; google.protobuf.Timestamp hidden_at = 3; }`, additive, no existing field or message touched. Payload of an `EventEnvelope` on `engagement.events`, `type` = `platform.engagement.v1.ReviewHidden`, keyed by listing id like `ReviewCreated`.
- **`platform-core/packages/proto/platform/audit/v1/audit.proto`**: catalogue comment `Action catalogue (17)` becomes `(18)` and lists `voucher.admin_create`. Comment only; wire format and generated code semantics unchanged.
- **Vendored copies** (byte-identical to source): `events.proto` into every repo that vendors it: `team-engagement`, `team-analytics` and `team-order` (team-order is in `consumer_copies_test.sh` REPOS, so it must not drift). `audit.proto` into every repo that already holds a copy: team-analytics, team-audit, team-domain, team-engagement, team-frontend, team-gateway, team-identity, team-order, team-payment, team-promotion, team-verification (all currently identical to source; keeping them identical avoids drift failures).
- **Generated code** in consumers is regenerated by `buf generate` where the repo commits it; `ReviewHidden` Go types appear in team-engagement and team-analytics.
- **Checks**: `buf lint` and `buf breaking --against` main on platform-core; `buf lint` in each consumer proto module; a copy-match script covering the new files.
- No new RPC, no new topic, no migration. Deploy order (from the initiative): team-analytics before team-engagement, because unknown types are dead-lettered. That ordering is enforced by slice dependencies, not by this slice.

## NFR

- Compatibility: change is wire-additive; `buf breaking` (rule set FILE) reports 0 findings against main. Old consumers ignore nothing new on the wire until engagement emits `ReviewHidden`.
- Latency/availability: none (schema only).
- Limits: `ReviewHidden` payload is 3 scalar fields, well under 1 KiB.

## Data classification

| Field | Class | Purpose | Basis | Retention |
|---|---|---|---|---|
| `review_id` | pseudonymous identifier | locate the hidden review in analytics | legitimate interest (moderation analytics) | analytics fact table policy |
| `listing_id` | non-personal identifier | partition key, join to listing | same | same |
| `hidden_at` | metadata | time of moderation | same | same |

No user id, reviewer id, review text or title is carried (same design as `ReviewCreated`). The audit catalogue change adds no data.

## Threat model

- **Assets:** the engagement event contract, the audit action catalogue, vendored proto copies.
- **Abuse cases:** (1) a later edit removes or renumbers `ReviewHidden` fields and silently breaks consumers, mitigated by `buf breaking`; (2) a consumer copy drifts from the source and decodes the wrong shape, mitigated by the copy-match check; (3) someone adds PII (reviewer id, text) to `ReviewHidden`, mitigated by a field-set assertion test.
- **Authz rule:** none at the schema level. Who may emit `ReviewHidden` (team-engagement outbox only) and who may write `voucher.admin_create` (admin path in team-promotion with `audit.write`) is specified in `engagement-review-hidden-event` and `promotion-shop-voucher-audit`.
