## Why

team-order is the largest hand-rolled service left: it carries its own config binder (`internal/config`), logger setup, tracing and auth interceptors (`internal/interceptor`), gRPC server build (`internal/grpcserver`), outbox relayer and claim store (`internal/events/relayer.go`, `internal/repository/outbox*.go`), two hand-written Kafka consume loops with a DLQ (`internal/consumer/run.go`, `internal/bootstrap/kafka.go`), an audit client (`internal/upstream/audit.go`), a principal-forwarding upstream interceptor (`internal/upstream/domain.go`) and an OpenFeature wrapper (`internal/featureflags`). go-sdk v1.0.2 provides all of it.

It also carries what the user ruled out on 2026-10-22: dependency switches `DATABASE_ENABLED`, `KAFKA_ENABLED`, `OUTBOX_ENABLED`, `FEATURE_FLAGS_ENABLED`; runtime in-memory repositories wired in `cmd/server/main.go` when the pool is nil (`NewInMemoryCartRepository`, `NewInMemoryOrderRepository`, `NewInMemoryReturnRepository`, `NewInMemoryShipmentRepository`, in-memory saga and processed-event stores) and the guard `RequireDurableStorage`; a nil promotion client that silently turns vouchers and flash prices off; a nil audit client (empty `UPSTREAM_AUDIT_ADDR`) and a `DisputeConsumerStartDecision` that silently skips the dispute consumer; and a flag client that degrades to "disabled" when Flipt cannot be set up. The liveness probe depends on the overall health status, which includes Kafka, so a Postgres or Kafka outage restarts the pod; the SDK separates readiness (overall) from liveness (`liveness`), and Kafka stops being a readiness condition.

Plan: `plans/go-sdk-migration/PLAN.md` (Step 2, order: 71 commits on main since the first migration; the plan lists order as the user of every SDK package). Main's behaviour wins over `origin/feat/go-sdk-v1-e2e`, which is reference only (`git show origin/feat/go-sdk-v1-e2e:team-order/<path>`). SDK requirements: `openspec/specs/go-platform-sdk`. This change builds on main with Q10 (order lifecycle), C4 (dispute refund consumer) and Q11 (multishop checkout) in place.

initiative: go-sdk-migration

## What Changes

- Module: require `github.com/buidangphuc/agora/platform-core/packages/go-sdk@v1.0.2`; no `replace`, no `third_party`. A new `Makefile` includes `../platform-core/make/go-service.mk` and lints with `../platform-core/packages/go-sdk/.golangci.yml`; the service holds no copy of either. `golangci-lint` is pinned as a `go tool` as in the SDK `go.mod`. No doc comments are added (revive doc-comment rules are off).
- Layout (ADR-0016): `cmd/server/main.go` -> `internal/app.Run(ctx, settings)`; `internal/config`; `internal/rpc` (was `handler` + `interceptor` + `grpcserver`); `internal/order` (was `service`); `internal/store` (was `repository`); `internal/events` (was `consumer` + envelope builders; the hand-written relayer is replaced by `events.NewRelayer`, a constructor over `outbox.Relayer`); `internal/upstream`. `internal/bootstrap`, `internal/featureflags`, `internal/interceptor`, `internal/grpcserver`, `internal/handler`, `internal/service`, `internal/repository` and `internal/consumer` no longer exist. The second binary `cmd/resync-commits` stays and is rebuilt on `config.Load`, `postgres.Open` and `upstream.NewClient`.
- **BREAKING (config)**: `ENV` is required (no `local` default); `SHUTDOWN_GRACE_SECONDS` becomes `SHUTDOWN_GRACE` (Go duration, `10s`) and `SHUTDOWN_DRAIN_DELAY` is added; `GRPC_REFLECTION_ENABLED` defaults to false (was true) and is refused in a strict ENV; `OUTBOX_CLAIM_LOCK_SECONDS` becomes `OUTBOX_CLAIM_LOCK` (`60s`); `FEATURE_FLAGS_EVAL_TIMEOUT_MS` becomes `FEATURE_FLAGS_EVAL_TIMEOUT` (`500ms`); `UPSTREAM_CALL_TIMEOUT_SECONDS` is removed (audit writes use the fixed SDK 2 s bound, no longer configurable; accepted); `OUTBOX_MAX_ATTEMPTS` is removed (the SDK relayer retries transient failures with backoff and parks only permanent ones); `LOG_KEY_FP_SECRET` is added. `UPSTREAM_AUDIT_ADDR`, `UPSTREAM_DOMAIN_ADDR`, `UPSTREAM_IDENTITY_ADDR` and `UPSTREAM_PROMOTION_ADDR` are required in every ENV (no fallback mode, no local default); in a strict ENV `KAFKA_BROKERS` and `LOG_KEY_FP_SECRET` are required too. The audit address no longer has an empty local mode.
- **REMOVED**: `DATABASE_ENABLED`, `KAFKA_ENABLED`, `OUTBOX_ENABLED`, `FEATURE_FLAGS_ENABLED`, `RequireDurableStorage` and `RequiresDurableStorage`, every runtime `NewInMemory*` wiring and the "IN-MEMORY repositories" warning, `DisputeConsumerStartDecision`, the nil promotion client mode ("vouchers are ignored", flash price off), the nil flag-evaluator "treat checkout as enabled" branch, the `flags = featureflags.Disabled` degrade, and `upstream.DialPromotion` returning `(nil, nil)` for an empty address, and `auditx.Dial` with an empty address yielding no writer. In-memory stores remain only as test fakes in `internal/store/fake`, imported by no non-test code. `OUTBOX_ENABLED=false` ("rows recorded, never relayed") no longer exists: the relayer always runs.
- **MOCK DATA**: team-order has no mock switch today (no `MOCK_*` key; the delivery ETA is a deterministic function of the city, not a provider). Nothing moves onto `pkg/mockdata` and `MOCK_DATA` is not declared; the `MOCK_MOMO` payment-method enum value is business data and unchanged.
- **Outbox**: SDK `outbox.Store` and `outbox.Relayer` replace the hand-rolled ones over the existing table `order_outbox_events`; migrations `0011`-`0022` (`0011` is the `processed_events` key swap under Consumers; `0012`-`0021` the outbox upgrade; `0022` requeues rows the old relayer parked as `failed`) upgrade it to the SDK v1 shape (`seq`, `topic`, `traceparent`) in order-preserving steps. Every order event is still written with `EnqueueTx` in the transition's own transaction (paid, cancelled, placed, payment reminder, completed, return refunded, return requested, shipped) and relayed to `order.events` keyed by `order_id`. Published rows are purged after 7 days by `outbox.Store.Purge` on an hourly `lifecycle.Every` component. The first rollout scales the old pods to 0 before the new pods start (Recreate once, so two relayers never run together).
- **Consumers**: the `payment.events` consumer (`PaymentSettled` -> PAID) and the C4 `engagement.events` dispute consumer (`DisputeResolved` -> return approve/refund) run on `consume.Consumer` with `kafkax.NewConsumerClient`, the shared producer as DLQ, and `consume.Options.KeyFP` from `LOG_KEY_FP_SECRET`. Consumer group ids and DLQ topic names are unchanged. The dedupe ledger is `consume.Dedupe` over `processed_events`; migration `0011` changes its primary key to `(consumer, event_id)`. Payment consumer: SDK retry (5 attempts) then DLQ; the retry base backoff changes from 200 ms (`RunConfig` default, uncapped doubling) to the SDK 100 ms doubling with a 30 s ceiling, and `FetchRetryBackoff` is removed (BREAKING, accepted by the recipe). Dispute consumer keeps "retry transient errors until applied, never DLQ" with `MaxAttempts` set to `math.MaxInt32`, `MaxBackoff` 5 s and `MaxPollRecords` 1; only permanent errors reach the DLQ.
- **Audit-first admin actions**: the four audited admin actions (`ForceFailSaga`, admin `UpdateOrderStatus`, admin `UpdateReturnStatus`, admin `CreateShipment`) and the dispute consumer write through `auditx.Gate`; failure returns `Unavailable` with message `audit trail unavailable` (was `audit trail unavailable; action not performed`). The audit connection uses `auditx.Dial(s.Audit, "service-team-order", "audit.write")`; the principal id stays `service-team-order` and the scope stays `audit.write` only.
- **Upstream principals**: domain, identity and promotion connections use `upstream.NewClient`. The stock RPCs (`ReserveStock`, `CommitReservation`, `ReleaseStock`) are sent with `upstream.WithServicePrincipal(ctx, "service-team-order", "listing.write")`; the voucher saga and flash hold RPCs with scope `promotion.reserve`; a read with no end-user principal (background) with scope `listing.read`; every other call forwards the buyer principal unchanged. The `x-principal-*` header code and `forwardMetadataInterceptor` are deleted.
- **Migrations**: the `server` binary gains `migrate up` (SDK `migrate.Up`, migrations embedded through `migrations/embed.go`); boot never migrates. Compose keeps `team-order-migrate` running the service image with `migrate up`; gitops runs the same command as an Argo PreSync Job (deploy-go-sdk-v1).
- **Health**: readiness is the overall status with the single check `postgres` (Kafka is not a readiness check; no upstream checker exists in the SDK); liveness is the `liveness` service. The chart sets `probes.livenessService: liveness` (deploy track).
- **Errors**: `grpcx.Status` with one service `ErrorTable`; unique-key violation 23505 maps to `AlreadyExists`; `context.Canceled` and `DeadlineExceeded` map to their gRPC codes; an unexpected error returns `Internal` "internal error" (the existing no-echo rule is kept, the text `<op> failed` changes). `clientErr` messages are unchanged.
- **Flags**: `flags.New` (OpenFeature + Flipt) replaces `internal/featureflags`; `checkout-enabled` keeps default true (fail open on a Flipt outage) and message "checkout is temporarily unavailable". An empty `FLIPT_ADDR` refuses boot.
- **Idempotency**: `CreateOrder` validates the `idempotency-key` metadata with `idempotency.Validate` (after trimming) and the metadata key and 255-byte limit come from the SDK constants.
- **Lifecycle**: the reservation sweep and the lifecycle sweep run as `lifecycle.Every` components; shutdown order is health drain, gRPC server stop, then relayer, consumers, sweepers and purge, then Kafka clients and the pool.
- **Resilience (behaviour change)**: `ReleaseStock` in compensation, cancel and sweeps runs under `resilience.Retry`. Baseline today (`releaseReservationWithRetry`): 3 attempts, any error code retried, backoff 100 ms x attempt, bounds tunable by `WithReleaseRetry(timeout, maxAttempts, backoff)`, 30 s per-release timeout and a 2 s inline budget on buyer cancel. After: still 3 attempts by default, same `WithReleaseRetry`, timeout and inline budget (all survive), but only `Unavailable` and `DeadlineExceeded` are retried (a non-retryable code is attempted once, was 3 times) and the delay follows the SDK backoff. `ReleaseFlashSaleStock` and `ReleaseReservation` stay best-effort, logged and never parked, as before. Tests that count release calls for a non-retryable code change their expected count from 3 to 1.
- **Not used**: `pagination` (no paged RPC in `order.proto`), `jwtx` (token verification stays at the gateway), `mockdata` (no mock switch), `testkit` only in tests. There is no payment upstream in team-order (it never calls team-payment).
- Specs: ADDED capability `order-service-runtime`; MODIFIED `order-admin-audit` (the four admin-action requirements and the audit client requirement lose the no-audit-client mode), `order-advertised-price` (no promotion-less mode). The shared `deploy-runtime` requirement "Services refuse unsafe configuration in staging and production" is MODIFIED only by change deploy-go-sdk-v1; the team-order bullet it needs is listed under the Deploy track of tasks.md.
- Accepted behaviour changes: the dispute consumer stalls its partition during a team-audit outage; the old `OUTBOX_MAX_ATTEMPTS` parking is replaced by SDK retry and the parked rows are requeued once.

## Non-functional requirements

- Availability: the service is ready only while the Postgres check passes (Kafka is not a readiness condition); liveness stays SERVING during a dependency outage (no restart loop). `migrate up` exits non-zero within 15 s when Postgres is unreachable. Boot fails fast (non-zero exit) when `DATABASE_URL` is empty or Postgres is unreachable, in every ENV.
- Latency: an order event's outbox row is claimed within one `OUTBOX_POLL_INTERVAL` (1 s default); a published row appears within 2 s of its enqueue (asserted by the relayer poll-interval scenario; no p95 figure is asserted). An audited admin action returns `Unavailable` within 3 s when team-audit is down (write bounded at 2 s). Existing RPC latency budgets are unchanged; the compensation retry keeps the 3-attempt bound of today.
- Throughput and limits: `OUTBOX_BATCH_SIZE` 100, `OUTBOX_CLAIM_LOCK` 60 s; payment consumer `MaxPollRecords` 500 and `MaxAttempts` 5; dispute consumer `MaxPollRecords` 1, `MaxBackoff` 5 s; idempotency key 1-255 printable ASCII bytes.
- Shutdown: health drains, `SHUTDOWN_DRAIN_DELAY` passes, the gRPC server stops within `SHUTDOWN_GRACE` (10 s), then the relayer, consumers and sweepers stop, then Kafka clients and the pool close.
- Delivery: at-least-once both ways; PAID, refunds and return transitions stay exactly-once in effect through the dedupe ledger and compare-and-set status updates.
- Deploy: the outbox upgrade uses `CREATE INDEX CONCURRENTLY` (no write lock beyond the brief `SHARE ROW EXCLUSIVE` in step `0014`); old pods are scaled to 0 before the PreSync migrate Job runs `0012`. Outbox retention: published rows 7 days.
- Gate: Docker-backed tests must run; a skipped test fails the gate.

## Data classification

| Field | Class | Purpose | Basis | Retention |
|---|---|---|---|---|
| `buyer_id`, `seller_id`, `actor_id`, `resolver_id` (user ids) | pseudonymous personal identifier | authorize and attribute orders, returns, shipments, audit events | legitimate interest (operating the marketplace order ledger) | database rows unchanged by this change; logs follow the platform log retention |
| `shipping_address` snapshot (name, phone, street, city) on orders | personal data | deliver the order | legitimate interest (contract performance) | unchanged by this change; never logged, never in audit metadata or outbox event metadata beyond what the existing events carry |
| `order_id`, `return_id`, amounts, voucher codes | transaction data | checkout, refund, audit metadata | legitimate interest | unchanged by this change |
| Kafka record key (`order_id`) in logs | derived identifier | diagnose consumer failures | legitimate interest | only `key_fp` (HMAC-SHA256 with `LOG_KEY_FP_SECRET`) is logged; platform log retention |
| `x-request-id`, traceparent in outbox rows | technical id | trace continuity | legitimate interest | purged with published outbox rows after 7 days |

No new personal field is collected. Per the user rule no DPO sign-off is required: legitimate interest, platform log retention.

## Threat model

- Assets: orders, carts, saga and reservation rows, returns and refund state, `order_outbox_events`, `processed_events`, the audit trail of admin actions, `LOG_KEY_FP_SECRET`.
- Abuse cases and controls:
  - Silent in-memory serving in a deployed environment (orders vanish on restart): no in-memory path exists; boot needs `DATABASE_URL` and a reachable Postgres in every ENV.
  - Silent loss of vouchers and flash prices when the promotion address is unset: the address is required in every ENV and the service constructor refuses a nil promotion client.
  - Debug surface: gRPC reflection is off by default and refused in a strict ENV.
  - Local defaults in a deployed environment: `ENV` has no default; every ENV requires the audit and upstream addresses and a strict ENV also requires brokers and the key secret.
  - Admin action without audit: `auditx.Gate` writes the event first and fails closed with `Unavailable`; the order, return or shipment is unchanged.
  - Dispute-driven refund while audit is down: the consumer retries until audit answers and changes nothing meanwhile; it never dead-letters a transient error.
  - Poison or replayed events: permanent errors park at once on the DLQ; redelivery is a no-op through the ledger and compare-and-set transitions.
  - Privilege confusion toward upstreams: stock calls carry only `listing.write`, voucher and flash calls only `promotion.reserve`, background reads only `listing.read`; the buyer principal and bearer token are never forwarded on those calls.
  - Identifier leakage in logs: consumer logs `key_fp` only; handler internal errors never echo driver or upstream text.
  - Outbox upgrade reorders events: step `0013` numbers old rows by `(created_at, event_id)`; ordering is tested.
  - Restart loop on dependency outage: liveness is independent of checks, and Kafka is not a check.
  - Two relayers publishing the same table during the outbox upgrade: old pods are scaled to 0 before new pods start; the SDK relayer claims rows with a lease anyway.
  - Boot-time schema change by a replica: `app.Run` never migrates; only the PreSync Job runs `migrate up`.
- Authorization rule (unchanged): every RPC needs a principal (anonymous rejected with `Unauthenticated`); owner-or-admin follows `isAdminOrUser` (the principal id equals the named user, or scope `order.admin`); `GetOrder` also admits a `service` principal with `order.read`; `ForceFailSaga` needs scopes `admin` and `order.admin`; seller-only and buyer-only RPCs keep their existing checks.
