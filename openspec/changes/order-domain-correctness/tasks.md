> Two tracks run in parallel: **CODE** (groups 1-8, per repo) and **E2E** (group 9, `platform-e2e` + owning repo
> `FEATURES.yaml`). Group 10 is the convergence gate.
> **Stacking:** the code lives on existing **unpushed** branches. Commit new work on top of them, never rebase or
> force-push: `team-order` `feat/order-integrity-guards`, `team-domain` `feat/release-requires-reservation-id`,
> `platform-core` `feat/commit-reservation`; `team-identity` (`feat/openspec-wave0-wave1`), `team-payment`
> (`hardening/sa-consistency`) continue on their checked-out branches. The tasks assume `CommitReservation`,
> release-by-`reservation_id`, `RELEASE_FAILED` parking, the atomic cancel claim and the `Idempotency-Key` saga header exist.
> Code order is by dependency: 1 (contract docs) -> 2 (identity, independent) -> 3 (domain) and 4 (payment) independent of each
> other -> 5..8 (`team-order`, in order). One commit per task that changes behaviour (bug fixes each get their own commit).
> **Integrated-stack rule:** 3.3 (the domain scope gate) can be built first, but the stack must run with 6.1 (team-order
> service principal) present, and production deploys 6.1 first (design "Migration Plan"). Run each repo's CI checks before every
> commit (`team-domain`: `make check`; `team-identity`: its `Makefile` check target; `team-order`/`team-payment`: `gofmt -l .`,
> `go vet ./...`, `go test ./...`; Postgres-backed tests with `TEST_DATABASE_URL`).
