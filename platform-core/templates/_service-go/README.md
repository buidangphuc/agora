# _service-go — Go gRPC service seed

A minimal, internally consistent **seed template** for a Go gRPC service on this
platform. It is a skeleton, not a finished service: expect placeholders and
`TODO`s where a real service fills in domain logic. It is shaped to compile and
run once you generate proto code and pin your dependencies.

What's wired for you:

- gRPC server with two chained interceptors — **auth** (bearer -> `Principal`)
  and **tracing** (`x-request-id` bridge) — plus the otelgrpc stats handler.
- gRPC **health** (serving) and **reflection** registered.
- One **seed RPC**: `platform.listing.v1.ListingService` (`GetListing`,
  `ListListings`) backed by an in-memory repository.
- OTLP/gRPC tracer, graceful shutdown on SIGINT/SIGTERM.
- Clean layering: `handler` (wire adapter) -> `service` (logic) -> `repository`
  (storage port + in-memory stub).

## Layout

```
cmd/server/main.go          entrypoint: server, interceptors, health, reflection
internal/interceptor/       auth.go (bearer+scopes), tracing.go (otel+request-id)
internal/handler/           gRPC adapter implementing the generated server
internal/service/           business logic (storage-agnostic)
internal/repository/        storage port + in-memory stub
proto-vendor/               pinned proto submodule (codegen input) — see its README
buf.gen.yaml                buf codegen -> ./generated (gitignored)
migrations/0001_init.sql    placeholder migration (golang-migrate)
Dockerfile Makefile .env.example .gitignore
```

## Instantiate a new service

1. **Rename the module.** Replace `github.com/your-org/team-service` everywhere
   (go.mod, all imports, `buf.gen.yaml` `go_package_prefix`) with your real repo
   path, e.g. `github.com/your-org/listing-service`.

2. **Pin the proto submodule.** Vendor platform-core's proto module under
   `proto-vendor/` at a tag — full steps in
   [`proto-vendor/README.md`](proto-vendor/README.md):

   ```bash
   git submodule add <platform-core-repo-url> proto-vendor
   (cd proto-vendor && git checkout proto/v0.1.0)
   ```

3. **Generate code.** Produces `./generated/...` (gitignored):

   ```bash
   make proto
   go mod tidy
   ```

4. **Configure + run.**

   ```bash
   cp .env.example .env    # set AUTH_BEARER_TOKEN, DATABASE_URL, OTEL endpoint
   make run
   ```

5. **Verify** (reflection is on):

   ```bash
   grpcurl -plaintext -H 'authorization: bearer <AUTH_BEARER_TOKEN>' \
     -d '{"id":"seed-1"}' localhost:50051 platform.listing.v1.ListingService/GetListing
   ```

## Merge gate

`make check` is the local merge-gate contract (gofmt, `go vet`, golangci-lint if
installed, `go test`). CI runs the same target — keep them identical.

## Rules (platform conventions)

- **Never hand-edit `generated/`.** It is regenerated by `make proto` and is
  gitignored (ADR-0001: each consumer generates in its own repo from a pinned
  proto tag; platform-core never writes code into this repo).
- **Own your database.** Only this service connects to its DB (DB-per-service).
  Other services reach this data over **gRPC**, never by sharing the database.
- **Cross-service calls are gRPC**, against the proto contract — no direct DB or
  in-process coupling across service boundaries.
- **Auth** is resolved to a `platform.common.v1.Principal` at the interceptor; handlers
  enforce coarse RBAC with `interceptor.RequireScopes(...)`. Bearer is a stub —
  real JWT/cookie handling lands per ADR-0003.
- **Tracing** is W3C trace-context via OpenTelemetry; the exporter is swappable
  (ADR-0004).
