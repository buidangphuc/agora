# Backend gaps seen by fe-platform

A screen never invents data the backend does not return. Each row is something a screen needs that the contract or a service does not give yet; the template shows an honest state instead. Add a row here before working around anything.

| ID | Screen | Need | What is missing | Template behaviour | Owner |
|---|---|---|---|---|---|
| G1 | `/products`, `/products/[id]` | Product image | `Listing` carries `image_keys` (storage keys) and no RPC returns a public URL for them (`GetImageUploadUrl` is upload only) | Neutral placeholder tile; cart and order lines use `image_url` when the service fills it | team-listing |
| G2 | `/products?q=` | Search results with title and price | `SearchHit` returns only `listing_id`, `score` and `stock`; there is no batch get for listings | One `GetListing` per hit (first 20 hits only); a hit that is not found is skipped | team-search, team-listing |
| G3 | `/shop/cart`, `/shop/checkout` | Currency for cart lines, subtotal and quotes | `Cart`, `CartItem`, `CheckoutGroupQuote` and `PreviewCheckoutResponse` carry amounts without a currency | Formatted with `DEFAULT_CURRENCY` from `lib/money.ts` (`VND`, the contract's own example) until the contract adds a currency; orders use their own `currency` | team-order |
| G4 | `/shop/confirmation` | One id for a checkout | `CreateOrder` returns one order per seller and there is no checkout or group id | Redirect carries the order ids (opaque, no personal data) and the page shows each order | team-order |
| G5 | forms | Which field failed | Backend errors are a message string; no field list | One form-level message chosen by error kind; the backend message is never put in a URL | all services |
| G6 | `/shop/checkout` | Payment methods offered | `PaymentMethod` lists mock methods next to COD with no way to ask which are enabled | All non-unspecified enum values are offered | team-payment |
| G7 | `/products` | Newest or sorted listings first | `ListListings` has no sort option and the first page of a populated catalogue is not newest-first | The list pages with the response cursor ("Next page"); a new listing can sit several pages in | team-listing |
| G8 | all three apps | One sign-in across buyer, seller and admin | Identity offers no one-time-code hand-off between apps; each app signs in on its own (ADR-0006) | Per-app sessions with distinct cookie names | team-identity |
| G9 | admin `/admin/vouchers` | Edit, stop or delete a platform voucher | `VoucherService` has only `CreateVoucher`, `GetVoucher`, `ListVouchers` (plus checkout reservation RPCs); no update, deactivate or delete | Screens are list, create and detail only; the create confirm dialog says a voucher cannot be changed after it is created | team-promotion |
| G10 | admin `/admin/vouchers/new` | Tell a duplicate voucher code apart | The insert error on a taken code is not mapped to `ALREADY_EXISTS`; the gateway returns `INTERNAL` | Generic "not created, the code may already exist" message | team-promotion |
| G11 | admin `/admin/vouchers/new` | Tell audit-down from promotion-down | Both reach the browser as `UNAVAILABLE` with the same sanitized gateway message | One message: audit or promotion is down and nothing was created | team-promotion, team-gateway |
| G12 | admin `/admin/campaigns` | Every flash-sale campaign, including scheduled and ended ones, and a way to cancel or edit one | `FlashSaleService` has only `ListActiveCampaigns` and `GetActiveFlashSale` for reads and no cancel or update RPC | The screen lists active campaigns only and states that scheduled, ended, cancel and edit are not available | team-promotion |
| G13 | admin `/admin/campaigns/new` | Safe retry after a timeout | `CreateCampaignRequest` has no idempotency key, so a retry can create a second campaign | A timeout closes the review dialog and asks the operator to check the active list before creating again | team-promotion |
| G14 | admin `/admin/campaigns/new` | Server-side checks on a new campaign | `CreateCampaign` validates only `listing_id`; the admin path skips the listing lookup, and price, stock cap and window are not checked; the kill-switch empties reads without saying so | The form requires positive integer price and stock cap and an end after the start and in the future; an empty active list is shown as "no campaigns" | team-promotion |
